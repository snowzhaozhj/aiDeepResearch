## 核心发现

<KeyFinding level="high">
  2026 年中，AI Coding Agent 的底层模型能力已高度趋同——SWE-bench Verified 上 GPT-5.5 与 Claude Opus 4.7 仅差 1.1 分（88.7% vs 87.6%）。但同一模型在不同 harness 下的表现波动达 10-36 分。ClawBench 的数据更加极端：scaffold 配置变化造成的分差是模型变化的 10 倍。**竞争已从「谁的模型更强」转向「谁的 harness 工程更好」。**
</KeyFinding>

<KeyFinding level="high">
  不存在「全能冠军」模型。GPT-5.5 在 SWE-bench Verified 和 Terminal-Bench 2.0 领先，Claude 在 SWE-bench Pro（更难问题）和 1-4 小时长任务上领先。不同 benchmark 暴露的优势维度完全不同，任何单一排名都是误导。
</KeyFinding>

<KeyFinding level="medium">
  指令文件标准的分裂（AGENTS.md vs CLAUDE.md）是生态碎片化的缩影。OpenAI 发起的 AGENTS.md 已获 Google、Cursor、Sourcegraph 加入并归入 Linux Foundation AAIF，但 Claude Code 仍读 CLAUDE.md。用户不得不用 symlink 变通桥接，这个问题至今未解决。
</KeyFinding>

## 一、模型能力趋同：harness 才是差异化因素

### 1.1 SWE-bench 上的趋同

<VerdictCard
  claim="底层模型能力高度趋同，harness 工程成为真正差异化因素：SWE-bench Verified 上 GPT-5.5 88.7% vs Claude Opus 4.7 87.6%（1.1 分差距），同一模型不同 harness 下波动 10-36 分"
  verdict="confirmed"
  votes="3-0"
>
  来源：[vals.ai/benchmarks/swebench](https://vals.ai/benchmarks/swebench)、[securityboulevard.com](https://securityboulevard.com)、[morphllm.com](https://morphllm.com)、[develeap.com](https://develeap.com)
</VerdictCard>

核心数据点：

- **SWE-bench Verified**：GPT-5.5 88.7% vs Claude Opus 4.7 87.6%（差距 1.1 分）
- **GPT 5.3 Codex vs Claude Opus 4.6 Thinking**：78.00% vs 78.20%（差距 0.2 分）
- **同一模型不同 harness**：表现波动 10-36 分

这组数据的关键含义：**当模型间差距仅为 1 分时，harness 工程带来的 10-36 分波动才是真正的胜负手。**

<VerdictCard
  claim="HarnessFix 论文量化了 harness 的独立贡献：15.2%-50.0% 的纯 harness 提升；ClawBench 发现 scaffold 配置变化造成的分差是模型变化的 10 倍"
  verdict="confirmed"
  votes="3-0"
>
  HarnessFix 论文和 ClawBench 基准测试提供了 harness 工程价值的定量证据。这不是边际优化，而是决定性因素。
</VerdictCard>

<Callout type="insight" title="非显而易见的推论">
  如果 harness 的影响是模型差距的 10 倍，那么「换一个更强的模型」可能是最低效的提升路径。相反，优化提示词策略、工具路由逻辑、上下文管理管线等 harness 层面的工作，ROI 远高于追逐最新模型。这对工具选型的启示是：评估一个 AI coding agent 时，应重点考察其 harness 工程质量，而非底层模型的 benchmark 排名。
</Callout>

### 3.2 第三方工具的涌现

多代理架构催生了专门的编排管理工具。[Nimbalyst](https://github.com/nimbalyst/nimbalyst)（MIT 协议，Electron 应用，770 stars）提供 Kanban 式并行 session 管理界面，让用户可视化管理多个并发 agent 任务的进度和状态。这类工具的出现说明：原生的多代理体验仍有显著的 UX 空白需要填补。

AAIF（AI Agent Interoperability Foundation）当前管辖范围包括：[MCP](https://modelcontextprotocol.io) 协议、AGENTS.md 标准、[Goose](https://github.com/block/goose) 项目、agentgateway。值得注意的是，MCP 最初由 Anthropic 发起，但已捐赠给 AAIF——这说明标准的所有权可以转移，CLAUDE.md 与 AGENTS.md 的分裂并非不可调和。

<Callout type="insight" title="实际影响">
  对于维护多 agent 工具链的团队，标准分裂意味着需要维护两套指令文件，或者使用 symlink/构建脚本来保持同步。这不仅是技术负担，更是认知负担——两种格式对指令的组织方式、作用域规则、优先级解析存在细微差异，容易导致一方的指令在另一方被忽略或误解。
</Callout>

  这是本研究中最重要的驳回。全票否决。
</VerdictCard>

「趋同」叙事的流行反映了一个认知陷阱：**功能列表的相似性被误读为架构的趋同**。四大工具确实都能做类似的事（写代码、运行命令、读文件），但实现方式差异极大：

- **Claude Code**：混合编排（ReAct + 确定性 JS 脚本），Dynamic Workflows 将控制流移出上下文窗口
- **Codex CLI**：迭代式代理循环 + Manager-Worker 多代理，编排仍在上下文窗口内
- **Cursor**：Background Agent 架构不透明，与 IDE 深度集成
- **Gemini CLI**：依赖第三方 harness（TongAgents）获得竞争力的 benchmark 表现

这些不是同一蓝图的变体，而是对「如何用 LLM 写代码」这个问题的根本不同的回答。趋同的是**用户可见的功能**，而非**底层架构**。正如本文第一节所述，架构差异通过 harness 层放大，最终体现为 10-36 分的实际表现差距。

## 八、开放问题

1. **Anthropic 信用池计费后重度用户成本增幅几何？** Pro 用户 $20 信用额度能支撑多少 agentic 工作量？缺乏公开的量化分析。建议社区在 6 月 15 日后收集真实使用数据。

2. **终端优先 vs IDE 集成的 MAU/DAU 对比数据缺乏。** Claude Code、Codex CLI 走终端优先路线，Cursor 走 IDE 集成路线，两种范式的用户规模和留存率对比数据不可得。这个数据对判断市场终局至关重要。

3. **AGENTS.md vs CLAUDE.md 标准分裂如何解决？** 鉴于 MCP 已从 Anthropic 捐赠给 AAIF 的先例，CLAUDE.md 是否会最终合并到 AGENTS.md？或者 Claude Code 会同时支持两者？目前无公开信号。

4. **CC Switch 95K stars 数据是否准确？** 研究过程中出现的这个数据点缺乏直接实证覆盖，无法确认也无法否认。

5. **SWE-bench 方法学问题是否会导致新的评估标准？** DeepSWE 的审计发现动摇了 SWE-bench 作为事实标准的地位。下一代 coding agent benchmark 应该如何设计才能抵抗 git 历史泄露等问题？

## 研究局限

<Callout type="warning" title="需要注意的局限">
  1. **时效性风险高**：Anthropic 6/15 计费变更和 Google 6/18 Antigravity 合并即将生效，本文数据将很快需要更新。
  2. **来源偏差**：[morphllm.com](https://morphllm.com) 为商业 LLM 代理产品，其发布的 benchmark 对比数据存在利益冲突。
  3. **覆盖不均**：Claude Code 和 Codex CLI 的公开技术信息远多于 Cursor 和 Gemini CLI，对比分析不可避免地偏向信息丰富的一方。
  4. **Benchmark 代表性**：SWE-bench、Terminal-Bench 等均为特定任务类型的测试，不能代表日常开发中的全部需求（如代码审查、架构设计、团队协作）。
  5. **被驳回声明的来源追溯**：部分被驳回声明的原始来源无法完全追溯，驳回理由基于「无法验证」而非「证伪」。
</Callout>
